# Техническое задание — О-комплекс

## Исходное задание работодателя
«Собрать с помощью ИИ простой скрипт/сервис, который принимает обращение клиента, сверяется с короткой базой знаний и выдает два блока: вежливый ответ клиенту + подсказку по допродажам для менеджера (на основе работы менеджера в диалоговом окне в AmoCRM). Формат сдачи: Видео-демонстрация (1–2 минуты) работы прототипа и рассказ о том, какие ИИ-инструменты помогли его собрать».

## Согласованный объём
Локальное веб-приложение с имитацией CRM. Работодатель подтвердил: эмуляции CRM достаточно; выбранная ниша кондиционеров согласована. Реальное подключение AmoCRM не входит в тестовое. Размещение на сервере отложено. Будущее размещение должно учитывать доступ из РФ. Тематика — вымышленная компания по продаже и установке кондиционеров. Разработка полностью в /Users/flutter/Desktop/o_complex_test.

## Пользовательский сценарий
Выбрать диалог → добавить сообщение клиента → подготовить ответ → получить ответ клиенту и отдельную внутреннюю рекомендацию → проверить, вставить в редактор, при необходимости изменить → отправить в имитируемый диалог.

## Функциональные требования
- Три стартовых сценария: подбор, отказ от монтажа, нестандартный монтаж. Дополнительный сценарий жалобы.
- История с ролями клиента и менеджера, сохранение между перезагрузками, новый диалог и явный сброс демонстрации.
- Редактируемая небольшая база: товары, услуги, правила. Валидация, сохранение на диске сервера.
- Помощник получает актуальную базу целиком и историю диалога. Результат содержит два блока, объяснение рекомендации и ссылки на пункты базы.
- Кнопки генерации, повторной генерации, вставки черновика и копирования.
- Отдельные состояния загрузки, отсутствия ключа, ошибки сети, ошибочного ответа модели. Ошибки не выдаются за успешный ответ.
- Demo доступен без аккаунтов и ключей, явно обозначен как правила. OpenRouter и Yandex API подключаются через .env; реальные запросы требуют ключа и доступа к модели.
- При изменении переписки или базы старый ответ больше нельзя считать актуальным.
- Интерфейс пригоден для записи экрана; все ресурсы шрифтов и графики локальные.

## Правила рекомендаций
Только факты из базы. Нехватка данных → уточнение. Никаких обещаний наличия и дат без данных. Не повторять отклонённую допродажу. При жалобе приоритет решению проблемы. Внутренняя подсказка никогда автоматически не отправляется клиенту. Менеджер остаётся ответственным за отправку.

## Критерии приёмки
Работают запуск, сборка, сохранение, редактирование, все сценарии и обработка ошибок. API-ключ отсутствует в клиентском коде. Автоматические тесты дополнены просмотром интерфейса. Реальная модель проверяется отдельно при наличии доступа. Подготовлены README, план, архитектура, отчёт проверок и сценарий видео.
